Fundamentos y modelado

Entiende el modelo relacional, las claves, las restricciones, la normalización y el modelado ER

  • Qué es: Sistema para organizar datos en tablas con filas y columnas, creado por Edgar Codd. Cada tabla representa una entidad del mundo real y las relaciones entre los datos se establecen de forma explícita.

    Por qué aprender: Base de todas las bases de datos SQL modernas. Entender el modelo relacional es un requisito previo para cualquier trabajo con bases de datos.

    Conceptos clave: Tabla (relación), Fila (tupla/registro), Columna (atributo), Dominio (tipo de datos)

  • Qué es: PK identifica cada registro de forma única. FK conecta tablas entre sí y establece relaciones entre entidades.

    Por qué aprender: Sin claves no hay integridad. FK impide que haya datos huérfanos y garantiza que las relaciones entre tablas sean válidas.

    Conceptos clave: PRIMARY KEY, FOREIGN KEY, REFERENCES, ON DELETE CASCADE, integridad referencial

  • Qué es: Reglas que la base de datos aplica para garantizar la validez de los datos (UNIQUE, NOT NULL, CHECK). Son restricciones declarativas en el esquema.

    Por qué aprender: Los datos no válidos cuestan caro. La validación en la base de datos es la última línea de defensa contra las inconsistencias.

    Conceptos clave: UNIQUE, NOT NULL, CHECK, DEFAULT, validación en capas

  • Qué es: Proceso de reorganizar tablas para reducir la duplicación y las dependencias. Sigue formas normales progresivas.

    Por qué aprender: Las tablas no normalizadas causan anomalías de inserción, actualización y eliminación. La normalización elimina la redundancia.

    Conceptos clave: 1FN (atomicidad), 2FN (dependencia parcial), 3FN (dependencia transitiva)

  • Qué es: Diagrama Entidad-Relación que modela la estructura antes de crear tablas. Representa visualmente las entidades y sus conexiones.

    Por qué aprender: Construir sin modelar es como construir sin planos. Evita el retrabajo y garantiza que el esquema cumpla con los requisitos.

    Conceptos clave: Entidad, atributo, relación, cardinalidad (1:1, 1:N, N:N)

  • Qué es: Criterios para decidir si una base de datos relacional es la mejor opción para tu caso de uso. No todos los problemas son un clavo.

    Por qué aprender: No todos los problemas necesitan SQL. Saber cuándo usarlo (y cuándo no) evita problemas de arquitectura.

    Conceptos clave: OLTP, datos estructurados, integridad sólida y cuándo NO usar el modelo relacional

SQL esencial

Domina los comandos fundamentales: CREATE, INSERT, SELECT, JOIN, GROUP BY y DELETE

  • Qué es: Comando DDL para definir tablas con columnas, tipos y restricciones. El punto de partida de cualquier base de datos.

    Por qué aprender: Todo comienza con la tabla. Un error en la estructura afecta a todo el sistema desde el inicio.

    Conceptos clave: CREATE TABLE, tipos (TEXT, INT, NUMERIC, SERIAL), PRIMARY KEY, REFERENCES

  • Qué es: Comandos DML para insertar registros nuevos y actualizar los existentes. La base del CRUD.

    Por qué aprender: CRUD básico. Todo sistema necesita crear y modificar datos de forma segura y eficiente.

    Conceptos clave: INSERT INTO...VALUES, UPDATE...SET...WHERE, RETURNING, upsert

  • Qué es: Comando para leer datos con filtros, ordenamiento y límite. El comando más usado en SQL.

    Por qué aprender: El 80% del trabajo con bases de datos consiste en leer. Dominar SELECT es esencial para cualquier profesional.

    Conceptos clave: SELECT, WHERE, ORDER BY, LIMIT, LIKE, IN, BETWEEN, IS NULL

  • Qué es: Operación que combina datos de dos o más tablas mediante claves. Reconstruye información normalizada.

    Por qué aprender: Los datos normalizados viven en tablas separadas. JOIN reconstruye la información completa cuando la necesitas.

    Conceptos clave: INNER JOIN, LEFT JOIN, RIGHT JOIN, ON, alias de tabla

  • Qué es: Agrupa registros y aplica funciones (COUNT, SUM, AVG, MAX, MIN). Transforma datos en bruto en información.

    Por qué aprender: Los informes y los dashboards dependen de agregaciones. Es el camino de los datos sin procesar a las decisiones.

    Conceptos clave: GROUP BY, HAVING, COUNT, SUM, AVG, funciones de ventana (introducción)

  • Qué es: Comando para eliminar registros de forma segura. Requiere mucho cuidado en producción.

    Por qué aprender: DELETE sin WHERE es un desastre. Aprender patrones seguros es obligatorio para cualquier DBA o desarrollador.

    Conceptos clave: DELETE FROM...WHERE, eliminación lógica, TRUNCATE, haz un backup antes de eliminar
