Fundamentos e Modelagem

Entenda o modelo relacional, chaves, restricoes, normalizacao e modelagem ER

  • O que e: Sistema de organizar dados em tabelas com linhas e colunas, criado por Edgar Codd. Cada tabela representa uma entidade do mundo real e as relacoes entre os dados sao feitas de forma explicita.

    Por que aprender: Base de todos os bancos SQL modernos. Entender o modelo relacional e pre-requisito para qualquer trabalho com banco de dados.

    Conceitos-chave: Tabela (relacao), Linha (tupla/registro), Coluna (atributo), Dominio (tipo de dados)

  • O que e: PK identifica cada registro unicamente. FK conecta tabelas entre si, estabelecendo relacionamentos entre entidades.

    Por que aprender: Sem chaves nao ha integridade. FK impede dados orfaos e garante que relacoes entre tabelas sejam validas.

    Conceitos-chave: PRIMARY KEY, FOREIGN KEY, REFERENCES, ON DELETE CASCADE, integridade referencial

  • O que e: Regras que o banco aplica para garantir validade dos dados (UNIQUE, NOT NULL, CHECK). Sao restricoes declarativas no schema.

    Por que aprender: Dados invalidos custam caro. Validacao no banco e a ultima linha de defesa contra inconsistencias.

    Conceitos-chave: UNIQUE, NOT NULL, CHECK, DEFAULT, validacao em camadas

  • O que e: Processo de reorganizar tabelas para reduzir duplicacao e dependencias. Segue formas normais progressivas.

    Por que aprender: Tabelas nao normalizadas causam anomalias de insercao, atualizacao e exclusao. Normalizacao elimina redundancia.

    Conceitos-chave: 1FN (atomicidade), 2FN (dependencia parcial), 3FN (dependencia transitiva)

  • O que e: Diagrama Entidade-Relacionamento que modela a estrutura antes de criar tabelas. Representa visualmente entidades e suas conexoes.

    Por que aprender: Construir sem modelar e como construir sem planta. Evita retrabalho e garante que o schema atenda aos requisitos.

    Conceitos-chave: Entidade, Atributo, Relacionamento, Cardinalidade (1:1, 1:N, N:N)

  • O que e: Criterios para decidir se banco relacional e a melhor opcao para seu caso de uso. Nem todo problema e um prego.

    Por que aprender: Nem todo problema precisa de SQL. Saber quando usar (e quando nao usar) evita problemas de arquitetura.

    Conceitos-chave: OLTP, dados estruturados, integridade forte, quando NAO usar relacional

SQL Essencial

Domine os comandos fundamentais: CREATE, INSERT, SELECT, JOIN, GROUP BY e DELETE

  • O que e: Comando DDL para definir tabelas com colunas, tipos e restricoes. O ponto de partida de qualquer banco de dados.

    Por que aprender: Tudo comeca com a tabela. Errar a estrutura impacta todo o sistema desde o inicio.

    Conceitos-chave: CREATE TABLE, tipos (TEXT, INT, NUMERIC, SERIAL), PRIMARY KEY, REFERENCES

  • O que e: Comandos DML para inserir novos registros e atualizar existentes. A base do CRUD.

    Por que aprender: CRUD basico. Todo sistema precisa criar e modificar dados de forma segura e eficiente.

    Conceitos-chave: INSERT INTO...VALUES, UPDATE...SET...WHERE, RETURNING, upsert

  • O que e: Comando para ler dados com filtros, ordenacao e limite. O comando mais usado em SQL.

    Por que aprender: 80% do trabalho com banco e leitura. Dominar SELECT e essencial para qualquer profissional.

    Conceitos-chave: SELECT, WHERE, ORDER BY, LIMIT, LIKE, IN, BETWEEN, IS NULL

  • O que e: Operacao que combina dados de duas ou mais tabelas usando chaves. Reconstroi informacao normalizada.

    Por que aprender: Dados normalizados vivem em tabelas separadas. JOIN reconstroi a informacao completa quando voce precisa.

    Conceitos-chave: INNER JOIN, LEFT JOIN, RIGHT JOIN, ON, alias de tabela

  • O que e: Agrupa registros e aplica funcoes (COUNT, SUM, AVG, MAX, MIN). Transforma dados brutos em informacao.

    Por que aprender: Relatorios e dashboards dependem de agregacoes. E o caminho de dados brutos para decisoes.

    Conceitos-chave: GROUP BY, HAVING, COUNT, SUM, AVG, funcoes de janela (intro)

  • O que e: Comando para remover registros com seguranca. Requer cuidado extremo em producao.

    Por que aprender: DELETE sem WHERE e desastre. Aprender padroes seguros e obrigatorio para qualquer DBA ou dev.

    Conceitos-chave: DELETE FROM...WHERE, soft delete, TRUNCATE, backup antes de deletar
