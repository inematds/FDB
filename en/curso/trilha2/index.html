⚡ Indexes and Transactions

Master indexes to speed up searches, ACID transactions to ensure consistency, and SQL best practices for professional queries.

What it is:

An auxiliary structure that speeds up queries by avoiding a full table scan.

Why learn:

Without an index, every search scans the entire table. Performance drops exponentially.

Key concepts:

B-tree, Hash, covering index, selectivity, maintenance cost

What it is:

Command to create indexes by choosing columns and a strategy.

Why learn:

The wrong index is worse than no index. It consumes space and slows down writes.

Key concepts:

CREATE INDEX, composite index, partial index, INCLUDE, UNIQUE INDEX

What it is:

Tools for viewing a query's execution plan and actual cost.

Why learn:

Without EXPLAIN, you're optimizing in the dark. It's an X-ray of performance.

Key concepts:

Seq Scan, Index Scan, Nested Loop, Hash Join, estimated vs. actual cost

What it is:

A set of operations that executes as an atomic unit (all or nothing).

Why learn:

A bank transfer without a transaction can lose money. ACID is essential.

Key concepts:

Atomicity, Consistency, Isolation, Durability, BEGIN/COMMIT/ROLLBACK

What it is:

A setting that defines which changes from other transactions a transaction can see.

Why learn:

Incorrect isolation causes dirty reads, phantom reads, and inconsistent data.

Key concepts:

READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE

What it is:

Patterns and habits for safe, performant, and maintainable queries.

Why learn:

Poorly written SQL and technical debt. Good practices today prevent incidents tomorrow.

Key concepts:

Prepared statements, avoid SELECT *, parameters, monitoring

2.2 ~45 min

🗂️ Database Types and Comparisons

Learn about the different types of databases, when to use each one, and how to make the right choice for each scenario.

What it is:

DBMSs with rigid schemas, SQL, ACID, and referential integrity.

Why learn:

More than 40 years of maturity. Standard for OLTP and transactional systems.

Key concepts:

PostgreSQL, MySQL, SQL Server, Oracle, SQLite, when to use each

What it is:

Store JSON/BSON documents without a fixed schema.

Why learn:

Fast iteration, variable content. Ideal for prototyping and CMS.

Key concepts:

MongoDB, Couchbase, aggregations, sharding, multi-document transactions

What it is:

Simple key->value mapping with sub-millisecond latency.

Why learn:

Cache, sessions, queues. Redis is the fastest database in the ecosystem.

Key concepts:

Redis, DynamoDB, TTL, persistence, pub/sub, Streams

What it is:

Store data by column (not by row), optimized for aggregations.

Why learn:

OLAP, data warehouse, BI. Compression and column scans are orders of magnitude faster.

Key concepts:

BigQuery, Redshift, ClickHouse, Snowflake, columnar compression

What it is:

Graphs model complex relationships. Time series optimize chronological data.

Why learn:

Social networks, recommendations, fraud (graphs). IoT, metrics, logs (time series).

Key concepts:

Neo4j, InfluxDB, TimescaleDB, Cypher, Prometheus

What it is:

A framework for selecting the right DBMS based on requirements.

Why learn:

A wrong choice costs months of rework. Decide with sound judgment and professionalism.

Key concepts:

OLTP vs OLAP, consistency vs availability, latency, cost, ecosystem
